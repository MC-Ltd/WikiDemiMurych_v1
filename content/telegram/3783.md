Во внутреннем представлении V8, есть миниму три разных обьекта представления строк.
Самые простые и самые эффективные - это те, которые являются ASCII - то есть первые 127 символов таблицы.
А вот дальше начинается бесовщина с unicode.

То есть когда наш код состоит только из US-ASCII то такой код внутри V8 представляется типичной однобайтовый представлением.

И как только появляется хоть один символ за этими приделами - начинается магия.
В том числе влияющая и на производительность


Например:
Кеширование байт кода, в условиях когда это нужно сделать сразу для всего JS бандла, без отслеживания того, какие функции в реальности выполняются в самом начале, то есть еще до старта выполнения самого бандла, произойдет только тогда, когда этот файл будет строго в UTF8 кодировке. И не дай бог там будет хоть один символ который нарушить правила UTF8
