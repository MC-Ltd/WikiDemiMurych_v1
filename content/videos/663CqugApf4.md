8:41 оптимизация кода в в8 происходит на уровне кода всей функции, в8 не оптимизирует по кусочкам, только всю функцию целиком

9:55, 12:35 инженеры решили как оптимизировать функцию, которая вызывается единожды, и содержит в себе длинный цикл (10_000+ итераций). Эта оптимизация называется OSR.

15:25 Позволяет оптимизировать маленький кусочек кода функции во время вызова этой функции

46:50 про пайплайн - маршрут который проходит код при выполнении. Этапы:
    1) весь код приводится к байткоду
    2) весь код который выполняется хотя бы один раз - спаркплаг
    3) моглев - приводит некоторый код к машинному коду, не применяя особых оптимизаций
    4) турбофан - собирает статистику и оптимизирует

51:00 как это все держать в голове? Первый триггер для обращения внимания это проверить те места, где код часто выполняется. Что сделать? Максимально изолировать код который повторяется в маленьких коротких контекстах.

55:14 пример

57:00 как только вы встречаете код, который многократно повторяется, нужно, например поместить цикл в отдельную функцию, Если функция маленькая и выполняет одну простую задачу, и эта функция попадает в долгий цикл, то вместо вызова функции, она может быть заинлайнена в цикл

1:02:40 другими словами: если у вас есть код, который многократно повторяется, подумайте, можно ли выделить часть этого кода в одельную функцию образом, про котором контекст этой функции не зависил бы от того места, которое многократно приводит к повторению, либо поместить тело функции в колбек:

var doOuter1 = ( theRes, theCur) => theRes + theCur;
while (theIterac--) {
    theRes += theArr.reduce(doOuter1, 0)
 } // 20 сек
VS
var doOuter1 = ( theRes, theCur) => theRes + theCur;
function doSum(theTarget) {
    return theTarget.reduce(doOuter1, 0)
}
while (theIterac--) {
     theRes += doSum(theArr);
} // 2 сек
ЛИБО
while (theIterac--) {
    theRes += theArr.reduce(( theRes, theCur) => theRes + theCur, 0) // эта функция изолирована внутри контекста редьюс, с этой функцией ничего произойти не может
 } // 2 сек
