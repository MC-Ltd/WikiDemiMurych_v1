Причем сделал на генераторах и с рекурсией. И даже не объяснил а чем решение то лучше.

Решение на генераторах очень удобно в данной задаче если мы хотим написать такой flatten который откидывал бы результат в поток постепенно, как только поток может продолжать прием данных. Потому что такой flatten не создал бы длинный список под результат. 

До генераторов следовало обсудить проблемы любого рекурсивного алгоритма а именно - небесконечность рекурсии.

После этого нужно было показать простейшую итеративную реализацию.

```
function flatten(arr) {
  const stack = [...arr];
  const result = [];

  while (stack.length) {
    const next = stack.pop();

    if (Array.isArray(next)) {
      stack.push(...next); //  Кандидат мог бы так же подсветить проблемы тут
    } else {
      result.unshift(next);
    }
  }

  return result;
}
```

Следующим шагом, предполагается что интервьюируемый укажет на проблемы производительности модификации массива. В большей степени проблема unshift.

Далее ожидается что интервьюируемый предложит структуру данных с быстрой вставкой и извлечением с обоих концов.

И уйдет от недостатков решения выше.

> ​@AsForJS Самое простое решение с алгоритмом наивного суммирования может иметь такой вид:
> const sumNaively = arr => arr.reduce(
>     (a, b) => a + b, 0
> );
> 
> Правда, в этом варианте могут быть потери точности из-за выхода за пределы безопасных целых чисел. Поэтому есть смысл применить компенсационное суммирование (алгоритм Кэхэна улучшенный Ноймайером), чтобы обезпечить более точный результат для вещественных чисел формата IEEE-754. В коде это можно реализовать примерно так:
> 
> const sumCompensatory = array => {
>     const {sum, comp} = array.reduce(
>         (acc, curr) => {
>             const {sum} = acc;
>             const t = sum + curr;
>             acc.comp += (
>                 Math.abs(sum) >= Math.abs(curr)
>                     ? (sum - t) + curr
>                     : (curr - t) + sum
>             );
>             acc.sum = t;
>             return acc;
>         },
>         {sum: 0, comp: 0}
>     );
>     return sum + comp;
> };

> **[@SerzhNesteruk](https://www.youtube.com/channel/UCvSxoIuRvinnq_mbU2KDTPA)** *[07.03.2024 19:24](https://www.youtube.com/watch?v=ICwDR01RgnA&lc=UgxngTzMpeGIQZwk4oh4AaABAg.9vESo0bMas3A0gt105XXxy)*

> По асимптотической сложности алгоритмы обеих функций эквивалентны. 🧐 То есть, они имеют идентичные оценки сложности в BigO-нотации, хотя и существенно отличаются между собой по производительности (как уже отмечалось, могут отличаться и результаты их работы).
> 1) Сложность по времени: O(n).
> Это значит, что для обработки массива длиной 1e+7 этими функциями будет затрачено примерно в 10 раз больше времени, чем для для массива длинной 1e+6.
> 2) Сложность по памяти: O(1).
> Это значит, что расход памяти при работе этих функций, не учитывая издержки на память самих входных данных, не будет существенно зависеть от размерности этих входных данных.
> 
> Хм... Где же здесь может быть ошибка? 🤔
>  Допускаю (поправьте меня, пожалуйста, если заблуждаюсь), что "ошибку" в оценке Big O здесь можно легко "обнаружить" при помощи абсолютно неподходящей для этой цели методологии. Которая в свою очередь, вероятно, основана на совершенно неверных представлениях о понятии асимптотической сложности алгоритма и о том, чем же оценка последней по своей сути отличается от измерения реального перформанса.

P.S. могу вам привести случай когда .concat будет работать в 359 раз медленнее чем вложенный цикл
пример из LeedCode:

var isArray = Array.isArray;
var flat = (array,maxDeep,level=0)=>{
    var resultArray = [];
    var item;

    for (item of array) {
        if (isArray(item) && level < maxDeep) {
            resultArray = resultArray.concat(flat(item, maxDeep, ++level));
            --level;
        } else {
            resultArray.push(item)
        }
    }
    return resultArray;
};
В том же LeedCode валится с ошибкой Time Limit Exceeded

но если заменить на этот код:

var isArray = Array.isArray;
var flat = (array,maxDeep,level=0)=>{
    var resultArray = [];

    for (const item of array) {
        if (isArray(item) && level < maxDeep) {
            const intermediateArray = flat(item, maxDeep, ++level);
            for(const intermediateRow of intermediateArray){
                resultArray.push(intermediateRow);
            }
            --level;
        } else {
            resultArray.push(item)
        }
    }
    return resultArray;
};

То все тесты проходят. Более того если сравнить время исполнения 1го варианта и 2го варианта, с условным вложенным массивом из 10000 элементов, то время исполнения с использованием concat будет +\- 2159мс в то время как вариант с вложенным циклом отработает всего за 8 +\- мс.
