То, что мы можем переписать методы в String.prototype , вообще не говорит о том, что мы изменяем поведение строкового типа данных. 
let myStr = 'examplestring';
myStr.toUpperCase === String.prototype.toUpperCase // true
При попытке вызвать метод на строке, примитивное значение 'examplestring' будет обёрнуто в декоратор - экземпляр конструктора String, который и имеет все необходимые методы. 
myStr.toUpperCase === new String(myStr).toUpperCase // тоже true. 
Любое чтение свойства или запись свойства в myStr приводит к тому, что это значение из myStr оборачивается в new String. Это происходит под капотом. Именно поэтому myStr.someProp = true не запишет это свойство в строку. Оно запишется в обёртку, которая после записи в неё свойства someProp удалится. Последующее чтение myStr.someProp вернёт undefined, потому что чтение свойства будет происходить у следующей созданной обёртки, у которой данного свойства нет. 
Если вывести myStr в console.dir, то ничего интересного мы там не увидим. Потому что строка как тип данных сама по себе тупая как пробка. В ней ничего нет. Свой функционал она получает исключительно благодаря оборачиванию в декоратор. Выведите new String('some text') в консоль и увидите объект с индексами для каждого символа, свойством length и ссылкой на String.prototype. 'some text' instanceof String //  false
Выше указанный предикат окончательно подтверждает, что примитивный строковый тип к конструктору String прямого отношения не имеет. Строка как тип (typeof 'my string example') не является экземпляром конструктора String. String - это класс объектных обёрток над строками для предоставления строкам определённого функционала. Без него строки сами по себе ничего не умеют, потому как они примитивны. Поэтому в JS изменить поведение строки как типа мы не можем. Мы изменяем поведение обёрток.

> **[@AsForJS](https://www.youtube.com/channel/UC8aUxVCtAmBtKXmYdPmzjeA)** *[18.04.2025 22:37](https://www.youtube.com/watch?v=atBBDQXDSGk&lc=UgywchYpIq2T5iGeQlF4AaABAg.AEefnNT1y-LAH4DgHC5jdD) (ред. 18.04.2025 22:39)*

> primitive value - это самый низкий уровень представления данных языка JavaScript.
> 
> Такие данные возвращают типы вида: Number, String, Boolean и так далее.
> 
> Однако это не означает, что типы которые возвращают primitive value являются Primitive Types. По причине того, что в языке JavaScript, эти типы нарушают главное правило любого примитивного типа - иметь одно единственное уникальное поведение. То есть работать всегда одним и тем же образом вне зависимости от условий. 
> 
> Все JS типы имеют особенности поведения, которые не возможно предсказать не зная алгоритма спецификации соответствующего этому условию. 
> Самый простой пример с типом Number, когда в JS мы оперируем числами с плавающей точкой согласно стандарту IEEE754, но при этом оказывается, что для Logical Expression мы игнорируем стандарт и просто отбрасываем дробну часть, возвращая новое число с плавающей точкой только уже без дробной части:
> var numberPi = 3.14;
> console.log( numberPi | 0 ); 
> 
> а так далее со всеми прочими типами.
> 
> 
> Единственными исключениями, которые можно было бы назвать примитивными типами являются: Null, Undefined, Symbol. 
> 
> При этом Вам никто не гарантирует, что в будущем в спецификации не возникнет "чего-то нового", что добавит "особенности" и в эти типы.
