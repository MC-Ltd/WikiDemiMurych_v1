Рекомендації по написанню JavaScript коду для максимальної оптимізації інтерпретатора (на основі V8)
Ось ключові, завершені поради від автора відео, зосереджені на уникненні "перешкод" для JIT-оптимізації. Кожна рекомендація включає коротке пояснення та приклад, щоб було легко застосувати. Рекомендації груповані за темами для зручності.
1. Оптимізація деструктуризації та присвоєнь

Уникайте деструктуризації масивів; використовуйте об'єкти або прямі доступи.
Деструктуризація масивів ([a, b] = arr) створює ітератор і проходить по елементах крок за кроком, що витратно. Об'єктна деструктуризація ({a, b} = obj) — швидша, бо прив'язує за ключами без ітерації.
Приклад: Замість [x, y] = coords використовуйте {x, y} = {x: coords[0], y: coords[1]}.
Не використовуйте rest-елементи в деструктуризації.[a, ...rest] = arr створює ітератор, виключає використані елементи та будує проміжний об'єкт — це дорого. Перепишіть без rest.
Приклад: Замість rest використовуйте slice(): const rest = arr.slice(2);.

2. Робота з генераторами та асинхронністю

Обмежуйте використання генераторів; обирайте простіші конструкції.
Генератори зберігають повний контекст на кожному кроці, що ускладнює оптимізацію. Використовуйте тільки для ітерацій; інакше — цикли чи проміси.
Приклад: Замість function* gen() { yield 1; } використовуйте звичайний цикл for.
Не зловживайте async/await; замінюйте на ланцюжки промісів або колбеки.
Async-функції — це обгортки над генераторами, що зберігають контекст на await, витрачаючи ресурси. Для простих операцій — прямі проміси чи колбеки.
Приклад: Замість async function() { const res = await fetch(); } — fetch().then(res => ...).

3. Оптимізація ланцюжків промісів та API

Скорочуйте ланцюжки промісів; уникайте зайвих об'єктів.
Довгі .then().then() створюють багато проміжних Promise, навантажуючи інтерпретатор. Об'єднуйте в один проміс або використовуйте колбеки.
Приклад: Замість p.then(a).then(b) — p.then(() => a().then(b)).
Використовуйте колбеки замість промісів для простих помилок/успіхів.
Колбеки не створюють Promise-об'єкти, економлячи ресурси.
Приклад:fs.readFile(path, (err, data) => { if (err) ... }) замість промісів.
Уникайте атомарних API (Atomics), якщо не потрібно.
Вони для багатопотоковості з shared memory — витратно. Використовуйте тільки для multi-agent.
Приклад: Не використовуйте Atomics.add() у звичайному коді.

4. Локальність та стабільність ідентифікаторів

Тримайте ідентифікатори локальними в функції; передавайте дані як аргументи.
Зовнішні посилання ускладнюють scope-ланцюжки та оптимізацію. Все локально — для агресивної оптимізації.
Приклад: Замість function foo() { return globalVar + x; } — function foo(globalVar, x) { return globalVar + x; }.
Зберігайте однаковий тип даних для ідентифікаторів протягом виконання.
Зміна типу (число → рядок) викликає deoptimization — інтерпретатор перегенерує код.
Приклад: Якщо let num = 1;, не робіть num = '1'; — тримайте як number.
Для чисел: уникайте перемикання між int/float.
JS-числа — int або float; зміна типу ламає оптимізацію. Визначайте явно (1.0 для float).
Приклад:let pi = 3.14; — не міняйте на pi = 3;.

5. Робота з об'єктами та циклами

Створюйте об'єкти одним конструктором з фіксованою послідовністю властивостей.
V8 оптимізує за "hidden classes"; зміна порядку/структури — deoptimization. Використовуйте Map для динамічних змін.
Приклад:const obj = {a:1, b:2}; — не додавайте obj.c = 3; пізніше.
Кешуйте повторні доступи до властивостей у локальні змінні.
Повторні obj.prop — повільні; присвойте в змінну для прямого доступу.
Приклад:const name = user.name; return name + ' ' + name; замість user.name двічі.
Оптимізуйте тіла циклів для частих ітерацій (>10k).
V8 оптимізує цикл окремо; тримайте код усередині ефективним, без зовнішніх залежностей.
Приклад: В for (let i=0; i<10000; i++) { sum += arr[i]; } — все локально.

Загальні поради

Тестуйте оптимізацію: Використовуйте інструменти як V8's --trace-opt або benchmarks (e.g., jsPerf) для перевірки.
Баланс: Ці правила для performance-critical коду; для читабельності — ігноруйте, якщо не критична швидкість.
Джерело оптимізацій: Базовано на внутрішній роботі V8 — читайте блог V8 для деталей.
