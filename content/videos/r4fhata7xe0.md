length у строки возвращает количество символов usc2 - т. е. 16-битных чисел, которые в большинстве современных языков называются char. Длина в байтах будет в 2 раза больше.
Но суррогатные пары при этом действительно не учитываются.
Проверить легко можно на кириллице:
"ы".length // 1
"ы".charCodeAt(0) // 1099
Очевидно, что значение 1099 в байт не помещается.

На эмоджи тоже можно проверить:
"👩🏼‍❤‍💋‍👨🏼".split("").map(x => x.charCodeAt(0)) // (14) [55357, 56425, 55356, 57340, 8205, 10084, 8205, 55357, 56459, 8205, 55357, 56424, 55356, 57340]
Все эти числа поместятся только в 16-битный тип, но не в 8-битный.

С учётом суррогатных пар оно состоит из 9 code point'ов, которые уже и в int16 не лезут:
[..."👩🏼‍❤‍💋‍👨🏼"].map(x => x.codePointAt(0)) // (9) [128105, 127996, 8205, 10084, 8205, 128139, 8205, 128104, 127996]
их же выдаст регулярка:
"👩🏼‍❤‍💋‍👨🏼".match(/./ug) // (9) ['👩', '🏼', '‍', '❤', '‍', '💋', '‍', '👨', '🏼']

Поиск эмоджи даёт 6 штук:
"👩🏼‍❤‍💋‍👨🏼".match(/\p{Emoji}/ug) // (6) ['👩', '🏼', '❤', '💋', '👨', '🏼']
но строка полностью из них не состоит:
"👩🏼‍❤‍💋‍👨🏼".match(/^\p{Emoji}+$/ug) // null

Так какая регулярка должна выдать результат в 1 "символ"?

> 
> Согласно спецификации языка JS, представление типа String опирается на стандарт Unicode и кодируется при помощи UTF16. Это кодирование требует 16 бит для реализации стандарта, что составляет 2 байта. 
> 
> Почему же тогда в языке JS, length применительно к типу String возвращает 1 если байтов два?
> 
> Потому, что согласно спецификации length возвращает не байты, а Code Point -  минимальная абстрактная единица Unicode символа.
> 
> При этом, все алгоритмы которые опираются на String обязаны исходить из того, что это именно так, если явным образом не сказано другого.
> 
> И нужно не забывать, что отображаемая сущность, может состоять из нескольких Code Point. 
> 
> Далее:
> Для того, чтобы JS код начал работать - нам нужна реализация спецификации. Которую почти никто не в чем не ограничивает, кроме обязательства чтобы имплементация выдавала тот же самый результат, что и алгоритм спецификации. 
> 
> То есть, тот факт, что спецификация описывает строки как Unicode в UTF16 кодировании, совершенно не означает что именно так та самая строка лежит внтури имплементации.

> 4.4.20 String value
> primitive value that is a finite ordered sequence of zero or more 16-bit unsigned integer values

> 6.1.4 The String Type
> The String type is the set of all ordered sequences of zero or more 16-bit unsigned integer values (“elements”) up to a maximum length of 2**53 - 1 elements.
> 
> The length of a String is the number of elements (i.e., 16-bit values) within it. The empty String has length zero and therefore contains no elements.
> 
> Operations that do interpret String values treat each element as a single UTF-16 code unit.
> 
> - A code unit that is not a leading surrogate and not a trailing surrogate is interpreted as a code point with the same value.
> - A sequence of two code units, where the first code unit c1 is a leading surrogate and the second code unit c2 a trailing surrogate, is a surrogate pair and is interpreted as a code point with the value (c1 - 0xD800) × 0x400 + (c2 - 0xDC00) + 0x10000. (See 11.1.3)
