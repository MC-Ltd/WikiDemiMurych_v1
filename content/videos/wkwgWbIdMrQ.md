> *1. Вещь первая*
> JavaScript является скриптовым языком.   То есть языком без своего ввода/вывода. То есть языком, который сам по себе существоать не может. То есть он должен быть куда-то встроен и использовать дополнительные API среды.
> 
> Например: 
> Браузер - это HOST куда встроен JavaScript. Без доступа к DOM API, JavaScript был бы почти бесполезен в браузере. То есть DOM API, это API предоставленое браузером (HOST) JavaScript. Но при этом, это API живет по своим правилам - не обязательно отвечающим спецификации языка JavaScript.
> 
> Это важно понимать именно для того, чтобы столкнувшись с проблемами в каком либо сторонним API - не обвинять в этом язык, и знать куда в какую другую спецификацию смотреть, чтобы найти проблему.
> 
> Например:
> Метод console.log принадлежит к API из стандарта HTML5 console. Где описаны правила его реализации. https://console.spec.whatwg.org/
> Что сразу же поясняет почему то же console.log работает иначе в NodeJS.
> Или почему API console может не оказаться в другой HOST среде, которая встраивает чистый ECMAScript.
> 
> 
> *2. Вещь вторая* 
> В JavaScript все определяется обьектом с прототипной моделью наследования. 
> 
> Например: кроме естественного восприятия того, как именно работают обьекты в коде JavaScript, по такому же принципу функционируют Environments (то что на жаргоне называют областями видимости). 
> То есть, когда программист понимает что такое прототипная модель наследования, обьяснить ему все особенности поведения  идентификаторов занимает 5 минут, с пояснением что Environments - это обьект, который имеет прототип - родительский Environments. И что именно Environments содержит в себе имена всех идентификаторов.
> 
> Точно так же описываются Records и все прочие фундаментальные вещи языка.
> 
> 
> *3. Вещь третья*
> JavaScript  является интерпретируемым языком, в котором основной базовой единицей кода -является выражение.   
> Если программист понимает, как работают Выражения  в JavaScript, он с легкостью даст ответ на большинство "продивнутых" вопросов на собеседованиях.
> 
> Например: 
> Сам по себе вопрос конечно уже не коректен, но он наглядно демонстрирует значимость 3 пунтка.
> Существует вопрос о потерянном контексте. 
> var/let/const theObj = {
>     name: "Murych",
>     sayName: function() {
>         console.log( 'My name is: ', this.name)
>     }
> }
> theObj.sayName();

> Чтобы ответить на Ваш вопрос, мне нужно сначала сказать следущее:
> 
> 1) В спецификации ECMAScript, то есть единственной официальной спецификации языка, такого понятия как примтивы, или примтивные типы - не существует.
> 
> 2) В спецификации ECMAScript, есть типы, которые возвращают Primitive Value, чего недостаточно для того чтобы записать их в примитивные типы или примитивы.
> 
> 3) Спецификация ECMAScript не регулирует правила того, каким именно образом представляются те типы, которые по умолчанию возвращают Primitive Value.
> 
> Если мы выносим за скобки, формальную / официальную часть то:
> 4) Примитивным типом принято считать тип, который содержит одни и те-же (подобные) данные (например числа) и при этом, поведение этого типа всегда одно и то-же вне зависимости от условий его использования.
> 
> В ECMAScript - все типы возвращающие Primitive Value (кроме undefined и null), имеют целый ряд специфических норм поведения. На которые может влиять программист. Например, для того же String, программист может определить элемент по индексу, которого в реальности в строке нет.
> 
> Уже только по этому, можно говорить о том, что примитивных типов или примтивов в JS не существует. Ну в крайнем случае, отдаленно, ими можно назвать тип Null и тип Undefined.
> 
> Далее. Поскольку спецификация ECMAScript никак не регламентирует процесс представления Primitive Value и более того, при операциях связывания заявляет об абстрактной операции bound (связывания), мы можем опираться только на конкретную реализацию этих типов в конкретном RunTime.
> 
> Например в RunTime V8 прямо сказано, что все типы представляют собой обьекты: 
> _JavaScript values in V8 are represented as objects and allocated on the V8 heap, no matter if they are objects, arrays, numbers or strings_
> https://v8.dev/blog/pointer-compression#value-tagging-in-v8
> 
> 
> *Вместо ИГОГО*
> 1] Официальная спецификация не содержит определения для примитивных типов.
> 
> 2] Официальная спецификация содержит только типы, которые возвращают по умолчанию Primitive Value.
> 
> 3] Условия использования типов, которые возвращают Primitive Value, не отвечают условиям, которые свойственны общепринятым нормам для Primitive Types.
> 
> 4] Официальная спецификация не регламентирует то, как именно программируются Primitive Value. Возлагая это на RunTime.
> 
> 5] Официальная спецификация содержит две операции: связывания и reference-like определение ссылки, которые автоматически заставляют RunTime определять такие типы как Обьекты или Структуры подобные обьектам.
